Undantekningar og pakkar

Hvað á pop() að gera ef bunkinn er tómur? Hvað ef notandinn slær inn „abc“ þegar beðið er um tölu? Undantekningar (exceptions) eru sérstök rás til að tilkynna og meðhöndla villuástand, aðskilin frá venjulegum skilagildum. Hér lærir þú try/catch/finally, throw og throws, muninn á athuguðum og óathuguðum undantekningum, að búa til eigin undantekningar, og hvernig pakkar skipuleggja kóðann og takmarka aðgang.

Af hverju ekki sérstök skilagildi?

Gamla leiðin er að skila „villugildi“: setYear skilar false, numPublications skilar -1. Það hefur galla:

  • Villan fer um sömu rás og venjuleg gildi; stundum er ekkert gildi laust (hvaða staða á bankareikningi táknar „reikningurinn var ekki til“?).
  • Merkingin er bara skjalfest óformlega og auðvelt að gleyma að athuga hana.
  • Kallandinn þarf að flækja kóðann með if/switch á skilagildum.

Undantekningar leysa þetta: sérstök rás, nákvæm villutegund (klasi), formleg yfirlýsing (throws) og þvinguð meðhöndlun.

try, catch og finally

try {
    int found = library.numPublications(year);   // getur kastað
    System.out.println(found + " books found.");  // keyrir EKKI ef kastað var
} catch (InvalidYearException e) {
    System.out.println("Invalid search year.");
} finally {
    System.out.println("Leit lokið.");            // keyrir ALLTAF
}
System.out.println("Áfram");
  • Ef undantekning kastast í try er afgangur try-blokkarinnar sleppt og keyrslan fer í fyrstu catch-blokk sem passar. Settu því allt sem á ekki að keyra eftir villu inn í try.
  • Ef engin undantekning kastast er öllum catch-blokkum sleppt.
  • finally keyrir alltaf: eftir try, eftir catch, og jafnvel þótt undantekningin sé ekki gripin eða return sé í try.
  • Eftir catch (eða finally) heldur keyrslan áfram á eftir try-setningunni, ekki þar sem villan varð.

Röð catch-blokka

Undantekningar mynda stigveldi, og catch fyrir yfirklasa grípur líka alla undirklasa hans. Raðaðu því frá sértækum til almennra; annars er seinni blokkin óaðgengileg (þýðingarvilla):

try { … }
catch (ArrayIndexOutOfBoundsException e) { … }  // sértækt fyrst
catch (RuntimeException e) { … }
catch (Exception e) { … }                        // almennt síðast
Throwable
├── Error                        (alvarlegt, t.d. OutOfMemoryError: ekki grípa)
└── Exception                    ← athugaðar (checked), t.d. IOException, FileNotFoundException
    └── RuntimeException         ← óathugaðar (unchecked)
        ├── ArithmeticException            (heiltala / 0)
        ├── NullPointerException           (aðferð á null)
        ├── ClassCastException             (rangt niðurkast)
        ├── IllegalArgumentException       (ógild færibreyta)
        │   └── NumberFormatException      (Integer.parseInt("abc"))
        ├── IndexOutOfBoundsException
        │   ├── ArrayIndexOutOfBoundsException
        │   └── StringIndexOutOfBoundsException
        └── java.util.InputMismatchException   (nextInt() fær ekki tölu)

throw og throws

public class InvalidYearException extends Exception {   // eigin, athuguð
    public InvalidYearException(String message) {
        super(message);                                   // geymir skilaboðin
    }
}

public int numPublications(int year) throws InvalidYearException {  // yfirlýsing
    if (year <= 1452) {
        throw new InvalidYearException("Engar prentaðar bækur fyrir " + year);
    }
    …
    return found;
}
  • throw (setning, í líkamanum) kastar undantekningarhlut; aðferðin hættir strax.
  • throws (í hausnum) lýsir yfir að aðferðin geti kastað þessari tegund.
  • e.getMessage() skilar skilaboðunum sem voru gefin smiðnum; e.toString() (eða println(e)) gefur „klasanafn: skilaboð“.
  • Í UNO kastar pop() á tómum bunka EmptyStackException, sem er skilgreind sem extends RuntimeException.

Þrjár leiðir til að bregðast við

  1. Grípa og meðhöndla (algengast), t.d. biðja notandann aftur um inntak.
  2. Grípa og kasta annarri: breyta tæknilegri villu í villu úr viðfangsefninu: catch (ArrayIndexOutOfBoundsException e) { throw new EndOfListException(); }. Kallandinn þarf þá ekki að vita að safnið er fylki.
  3. Láta hana fljúga upp: grípa ekki, heldur lýsa yfir með throws og láta aðferðina sem kallaði sjá um hana. Ef enginn grípur hana stöðvar JVM forritið og prentar staflarakningu (stack trace): Exception in thread "main" java.lang.ArithmeticException: / by zero at …

Aldrei: catch (Exception e) { }, þ.e. grípa og gera ekkert. Þá eru allar villur faldar.

Fullunnið dæmi: öruggt inntak (HumanPlayer)

Scanner stdin = new Scanner(System.in);

    System.out.print("\nChoose card to discard: ");
    try {

    } catch (InputMismatchException e) {

} while (choice < 0 || choice > index);

Án stdin.next() í catch yrði ógilda orðið áfram í inntakinu og lykkjan endalaus.

Rakning: hvað prentast?

static int f(int x) {
    try {
        System.out.print("a");
        int y = 10 / x;
        System.out.print("b");
        return y;
    } catch (ArithmeticException e) {
        System.out.print("c");
        return -1;
    } finally {
        System.out.print("d");
    }
}
// í main:
System.out.println(" " + f(2));
System.out.println(" " + f(0));
abd 5
acd -1

finally keyrir áður en aðferðin skilar, líka þegar return er í try eða catch. Prentunin í main kemur á eftir, því f er kallað áður en strengurinn er prentaður.

Pakkar og aðgangur

Pakki (package) er nafnasvæði og mappa fyrir skylda klasa. Lokaútgáfa UNO-spilsins skiptir kóðanum í tvo pakka:

// src/uno/game/StackOfCards.java
package uno.game;
class StackOfCards { … }            // engin aðgangsorð: pakkaaðgangur

// src/uno/players/ComputerPlayer.java
package uno.players;
import uno.game.Card;               // klasar úr öðrum pakka þarf að flytja inn
import uno.game.Player;
public class ComputerPlayer extends Player { … }
  • package verður að vera fyrsta setning skrárinnar; mappan verður að heita eins (uno/game/).
  • import pakki.Klasi; eða import pakki.*; gerir klasann aðgengilegan með stuttu nafni. java.lang (String, Math, System, Integer) er alltaf fluttur inn; java.util (Scanner, Arrays, ArrayList) þarf að flytja inn.
  • Pakkaaðgangur (ekkert aðgangsorð, ~ í UML) leyfir klösum í sama pakka að nota klasann eða aðferðina, en engum utan hans. Í UNO er StackOfCards þannig falinn utan uno.game: leikmennirnir sjá bara DrawPile og DiscardPile.

Samantekt

  • try: afgangi sleppt eftir kast; catch: fyrsta sem passar; finally: alltaf.
  • catch frá sértæku til almenns.
  • throw new X(…) kastar; throws X lýsir yfir.
  • Athugaðar (Exception): „catch or declare“. Óathugaðar (RuntimeException): engin krafa.
  • Eigin undantekning: class MyException extends Exception { … super(message); }
  • Pakki = mappa; package fyrst, import svo; enginn aðgangur = pakkaaðgangur.
