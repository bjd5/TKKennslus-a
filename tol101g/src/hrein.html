Hrein klasar og viðmót

Hvað er flatarmál „marghyrnings“ almennt? Það er ekki hægt að reikna nema vita hvort hann er þríhyrningur eða rétthyrningur. Hrein klasar (abstract classes) og viðmót (interfaces) leyfa þér að lýsa hvað hlutir geta gert án þess að segja hvernig, og láta undirklasana fylla í. Þetta er síðasta stóra hugtakið í hlutbundnu hönnuninni.

Hreinir klasar (abstract)

public abstract class Polygon {
    protected Point[] corners;

    protected double distance(Point p, Point q) {
        return Math.sqrt(Math.pow(p.getX() - q.getX(), 2)
                       + Math.pow(p.getY() - q.getY(), 2));
    }

    public double calcPerimeter() {              // venjuleg aðferð
        double perimeter = 0;
        for (int i = 0; i < corners.length; i++) {
            perimeter += distance(corners[i], corners[(i + 1) % corners.length]);
        }
        return perimeter;
    }

    public abstract double calcArea();           // hrein aðferð: enginn líkami, ;
}
  • Hrein aðferð (abstract method) hefur undirskrift en engan líkama; hún endar á ;.
  • Klasi sem hefur hreina aðferð verður að vera merktur abstract.
  • Ekki er hægt að búa til hlut af hreinum klasa: new Polygon() er þýðingarvilla. En breyta má vera af taginu: Polygon p = new Triangle(…);
  • Undirklasi verður að útfæra allar hreinu aðferðirnar, annars verður hann sjálfur að vera abstract.
  • Hreinn klasi getur samt haft eigindi, smiði og venjulegar aðferðir (smiðurinn er kallaður með super(…) úr undirklasanum).

Í geometry-dæminu reiknar Polygon ummálið eins fyrir alla marghyrninga (calcPerimeter), en hver undirklasi útfærir calcArea á sinn hátt: Triangle með formúlu Herons og Rectangle sem breidd × hæð. Í UNO er Player hreinn klasi með hreinu aðferðinni playTurn, sem HumanPlayer og ComputerPlayer útfæra.

Sniðmátsaðferð: þegar venjuleg aðferð í hreinum klasa kallar á hreina aðferð (t.d. toString() sem kallar á calcArea()) ákveður yfirklasinn skrefin og undirklasarnir innihald þeirra. Breytileg binding sér um að rétta útgáfan keyri.

Viðmót (interface)

Viðmót er „samningur“: listi af aðferðum sem klasi lofar að útfæra. Klasi útfærir viðmót með implements:

public interface Shape {
    double PI_ISH = 3.14;          // fastar eru sjálfkrafa public static final
    double area();                 // aðferðir eru sjálfkrafa public abstract
    default String describe() {    // default-aðferð (Java 8+) hefur líkama
        return "Lögun með flatarmál " + area();
    }
}

public class Circle implements Shape {
    private double r;
    public Circle(double r) { this.r = r; }
    @Override
    public double area() { return Math.PI * r * r; }   // verður að vera public
}
  • Viðmót hefur engin hlutbundin eigindi og enga smiði; ekki er hægt að gera new Shape().
  • Klasi má útfæra mörg viðmót (implements A, B, C) en bara erfa einn klasa: class HumanPlayer extends Player implements Comparable<HumanPlayer>.
  • Viðmót má erfa önnur viðmót með extends.
  • Útfærslan verður að vera public (því aðferðir viðmótsins eru public).

Comparable: að raða eigin hlutum

Arrays.sort kann að raða tölum og strengjum, en hvernig á að raða spilum? Klasinn útfærir Comparable<T> og aðferðina compareTo, sem skilar neikvæðu ef this á að koma á undan, 0 ef jafnt og jákvæðu ef á eftir:

public class Card implements Comparable<Card> {
    private int number;
    private char color;
    …
    @Override
    public int compareTo(Card other) {
        if (color != other.color) {
            return color - other.color;      // fyrst eftir lit (B < G < R < Y)
        }
        return number - other.number;        // svo eftir tölu
    }
}

Card[] hand = { new Card(7, 'R'), new Card(2, 'G'), new Card(5, 'R') };
Arrays.sort(hand);                           // notar compareTo
System.out.println(Arrays.toString(hand));   // [G2, R5, R7]

Fullunnið dæmi: launagreiðslur

abstract class Employee implements Comparable<Employee> {
    private String name;
    public Employee(String name) { this.name = name; }
    public String getName() { return name; }
    public abstract double pay();                     // hver tegund reiknar sjálf
    public int compareTo(Employee o) {                // raða eftir launum
        return Double.compare(pay(), o.pay());
    }
    public String toString() { return name + ": " + pay(); }
}

class Salaried extends Employee {
    private double monthly;
    public Salaried(String n, double m) { super(n); monthly = m; }
    public double pay() { return monthly; }
}

class Hourly extends Employee {
    private double rate; private int hours;
    public Hourly(String n, double r, int h) { super(n); rate = r; hours = h; }
    public double pay() { return rate * hours; }
}

Employee[] staff = { new Salaried("Anna", 900), new Hourly("Kári", 20, 30) };
Arrays.sort(staff);
for (Employee e : staff) System.out.println(e);
Kári: 600.0
Anna: 900.0

Samantekt

  • Hrein aðferð: public abstract double calcArea(); án líkama.
  • Hreinum klasa má ekki new-a; undirklasi útfærir allar hreinu aðferðirnar eða er sjálfur abstract.
  • Hreinn klasi getur haft eigindi, smiði og venjulegar aðferðir.
  • Viðmót: aðferðir sjálfkrafa public abstract, fastar public static final; implements mörg.
  • Comparable<T> + compareTo → Arrays.sort virkar á eigin hluti.
  • UML: skáletur = abstract; «interface»; brotin lína + ▷ = implements.
