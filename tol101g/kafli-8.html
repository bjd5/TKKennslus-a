Klasar og hlutir

Tengist: Miðannarpróf 2 og lokapróf: smiðir, get/set, static, UNO-spilið

Hlutbundin forritun lítur á forritið sem kerfi af hlutum sem vinna saman og kalla á aðferðir hvers annars. Hér lærir þú að skilgreina eigin klasa með eigindum, smiðum og aðferðum, búa til hluti með new, hjúpa ástand með private og get/set-aðferðum, og muninn á static og hlutbundnu. Dæmin koma úr UNO-spilinu og Circle-æfingunni.

Klasi og hlutur

Klasi (class): skilgreining á sameiginlegum einkennum safns hluta: heiti og tög eiginda og undirskriftir og útfærslur aðferða. Skilgreindur þegar forritið er hannað. „Teikningin“.

Hlutur (object, instance): einstakt eintak af klasa með sín eigin gildi á eigindunum. Búinn til (og eytt) á meðan forritið keyrir. „Bíllinn sem smíðaður er eftir teikningunni“.

Hver hlutur hefur ástand (state), sem eigindin skilgreina, og hegðun (behavior), sem aðferðirnar skilgreina. Ástandið er venjulega hjúpað (encapsulated): aðeins aðferðir hlutarins sjálfs mega breyta því, svo þær geti tryggt að það sé alltaf gilt.

Klasinn Card

public class Card {
    private int number;        // eigindi (attributes, instance variables)
    private char color;

    public Card(int number, char color) {   // smiður (constructor)
        this.number = number;  // this.number er eigindið, number færibreytan
        this.color = color;
    }

    public int getNumber() { return number; }   // get-aðferð (getter)
    public char getColor() { return color; }

    public boolean matches(Card other) {         // „business“-aðferð
        return number == other.number || color == other.color;
    }

    public String toString() {
        return "" + color + number;             // t.d. "R7"
    }
}
Card c = new Card(7, 'R');     // new býr til hlut og kallar á smiðinn
Card d = new Card(7, 'G');
System.out.println(c);          // R7   (println kallar á toString)
System.out.println(c.matches(d) + " " + d.getColor());   // true G

Smiðir

  • Smiður heitir nákvæmlega það sama og klasinn og hefur ekkert skilatag (ekki einu sinni void).
  • Hann er kallaður sjálfkrafa með new og á að koma hlutnum í gilt upphafsástand.
  • Ef klasinn hefur engan smið býr Java til sjálfgefinn smið (default constructor) án færibreyta. Um leið og þú skrifar einhvern smið hverfur sá sjálfgefni: new Card() verður þá þýðingarvilla nema þú skrifir hann sjálf(ur).
  • Smiðir má yfirhlaða, og einn smiður getur kallað á annan með this(…) í fyrstu línu.
public Circle(double x, double y, double r) {
    this.x = x;
    this.y = y;
    setR(r);              // notar setterinn svo staðfestingin gildi líka hér
}
public Circle(double r) {
    this(0, 0, r);        // kallar á hinn smiðinn
}

Eigindi sem smiðurinn setur ekki fá sjálfgefin gildi: 0, false eða null (ólíkt staðværum breytum, sem verður að frumstilla).

Lykilorðið this

this er tilvísun á hlutinn sjálfan, þann sem aðferðin var kölluð á. Það þarf þegar færibreyta skyggir á (shadows) eigindi með sama nafni: this.r = r;. Án this væri r = r; gildisveiting færibreytunnar í sjálfa sig, og eigindið yrði 0.

Hjúpun: private, get og set

Reglan í námskeiðinu: eigindi eru private; aðgangur fer í gegnum public aðferðir: smið, get-aðferðir (lesa, mögulega með umbreytingu), set-aðferðir (skrifa, mögulega með staðfestingu) og aðrar aðferðir sem vinna með eigindin. Setter getur hafnað eða lagað ógild gildi:

public void setR(double r) {
    if (r < 0) { r = r * -1; }   // neikvæður radíus verður jákvæður
    this.r = r;
}

Ekki þurfa öll eigindi get- og set-aðferðir. Spil (Card) breytir ekki um lit, svo það hefur bara getters: það er óbreytanlegt (immutable), eins og String.

Hlutir eru tilvísanir

Eins og fylki: breyta af tagi Card geymir tilvísun á hlut. Card c2 = c1; býr ekki til nýtt spil; bæði nöfnin vísa á sama hlutinn. Þegar hlutur er sendur í aðferð er tilvísunin afrituð, svo aðferðin getur breytt ástandi hans:

public static void check(Card card) {
    card.setNumber(card.getNumber() + 1);
    System.out.println(card.getNumber());
}

Card c = new Card(5, 'G');
System.out.println(c.getNumber());
check(c);
System.out.println(c.getNumber());
5
6
6

(Hér hefur Card fengið setNumber.)

null þýðir „vísar ekki á neinn hlut“. Kall á aðferð í gegnum null-tilvísun kastar NullPointerException. == á hlutum ber saman tilvísanir; til að bera saman innihald þarf klasinn sína eigin equals-aðferð.

Hlutur sem engin tilvísun bendir lengur á er ruslasafnaður (garbage collected) sjálfkrafa.

static og hlutbundið

Hlutbundið (instance)static (klasa-)
Eigindihver hlutur hefur sitt eintakeitt eintak sem allir hlutir deila
Aðferðkölluð á hlut: c.getNumber(); hefur thiskölluð á klasann: Math.max(…); hefur ekkert this
Má notaöll eigindi og aðferðiraðeins static eigindi og aðferðir (beint)
public class Player {
    private static int count = 0;   // sameiginlegt
    private int id;                 // eitt á hvern leikmann

    public Player() {
        count++;
        id = count;
    }
    public static int getCount() { return count; }
}

Algeng þýðingarvilla: að nota hlutbundið eigindi eða aðferð beint inni í static main („non-static variable cannot be referenced from a static context“). main tilheyrir klasanum, ekki neinum hlut, svo þú þarft fyrst að búa til hlut með new.

Fullunnið dæmi: StackOfCards

Hlaði (stack) er „síðast inn, fyrst út“ (LIFO), eins og bunki af spilum. Hann er útfærður með fylki og vísi á efsta spilið:

public class StackOfCards {
    private Card[] cards;
    private int top;                 // vísir efsta spils; -1 ef tómur

    public StackOfCards() {
        cards = new Card[112];
        top = -1;
    }
    public void push(Card card) { cards[++top] = card; }   // hækka fyrst, svo geyma
    public Card peek()          { return cards[top]; }
    public Card pop()           { return cards[top--]; }   // skila, svo lækka
    public boolean isEmpty()    { return top == -1; }

    public String toString() {
        String result = "";
        for (int i = 0; i <= top; i++) {     // bara notuðu hólfin
            result += cards[i] + ", ";
        }
        return result;
    }
}

Klasar í UML

UML-klasarit sýnir klasann sem kassa með þremur hólfum: nafn, eigindi og aðferðir. Tag kemur á eftir nafni með tvípunkti og aðgangur er táknaður með + - # ~. static er undirstrikað.

┌─────────────────────────────┐
│ Card                        │
├─────────────────────────────┤
│ - number : int              │
│ - color : char              │
├─────────────────────────────┤
│ + Card(number : int,        │
│        color : char)        │
│ + getNumber() : int         │
│ + getColor() : char         │
│ + matches(other : Card)     │
│        : boolean            │
│ + toString() : String       │
└─────────────────────────────┘
public class Card {
    private int number;
    private char color;
    public Card(int number, char color) {…}
    public int getNumber() {…}
    public char getColor() {…}
    public boolean matches(Card other) {…}
    public String toString() {…}
}

Nafnavenjur: klasar í eintölu með stórum staf (DiscardPile), eigindi og aðferðir með litlum staf (getColor), fastar í hástöfum (MAX_CARDS).

Samantekt

  • Klasi = teikning; hlutur = eintak búið til með new.
  • Smiður: sama nafn og klasinn, ekkert skilatag; sjálfgefinn smiður aðeins ef enginn annar er til.
  • this.x = x; þegar færibreyta skyggir á eigindi; this(…) kallar á annan smið.
  • Eigindi private; get/set public, setter getur staðfest.
  • Hlutbreytur geyma tilvísanir; null → NullPointerException.
  • static: eitt eintak á klasa; ekkert this.
