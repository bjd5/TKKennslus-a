Aðferðir

Tengist: Miðannarpróf 1 og lokapróf: færibreytur, skilagildi, yfirhleðsla

Aðferðir (methods) gefa kóðabút nafn svo hægt sé að nota hann aftur og aftur, og brjóta stórt vandamál í lítil. Hér lærir þú að skilgreina og kalla á aðferðir, hvað gerist við færibreyturnar (gildisfærsla), hvenær return er nauðsynlegt, svið breyta og yfirhleðslu.

Að skilgreina aðferð

/**
 * Reiknar base í veldinu exp.
 * @param base grunntalan
 * @param exp  veldisvísirinn (≥ 0)
 * @return base^exp
 */
public static double pow(double base, int exp) {   // haus (undirskrift)
    double result = 1;                              // líkami
    while (exp > 0) {
        result = result * base;
        exp--;
    }
    return result;                                  // skilagildi
}

Undirskrift (signature) aðferðar er nafnið og tög færibreytanna: pow(double, int). Skilatagið er ekki hluti af undirskriftinni.

Að kalla á aðferð

public static double area(double r) {
    return Math.PI * pow(r, 2);       // aðferð kallar á aðra aðferð
}

public static void main(String[] args) {
    double a = area(3.0);             // skilagildið er notað í segð
    System.out.println(pow(2, 10));   // 1024.0  (2 er víkkað í 2.0)
    pow(5, 2);                        // leyfilegt, en skilagildinu er hent
}

Við kall eru raungildin (arguments) metin og afrituð í færibreyturnar (parameters), í sömu röð. Fjöldi, röð og tög þurfa að passa (með sjálfvirkri víkkun, t.d. int → double). Þegar aðferðin klárast (eða return er keyrt) heldur keyrslan áfram þar sem kallað var.

Hvert kall fær sinn eigin ramma (frame) á kallhlaðanum (call stack) með færibreytum og staðværum breytum. Ramminn hverfur þegar aðferðin skilar.

void og return

  • Aðferð með skilatag (t.d. int) verður að skila gildi af því tagi á öllum leiðum. Annars er það þýðingarvilla („missing return statement“).
  • return hættir í aðferðinni strax; kóði á eftir því í sömu grein keyrir ekki.
  • void-aðferð skilar engu. Hún getur notað return; (án gildis) til að hætta snemma.
public static String sign(int n) {
    if (n > 0) {
        return "plús";
    } else if (n < 0) {
        return "mínus";
    }
    return "núll";              // án þessarar línu: missing return statement
}

public static boolean isEven(int n) {
    return n % 2 == 0;          // betra en if (…) return true; else return false;
}

Prenta eða skila? Ef verkefnið segir „skrifaðu aðferð sem skilar…“ á aðferðin að nota return, ekki System.out.println. Sá sem kallar ákveður hvað er gert við gildið.

Gildisfærsla (pass by value)

Java afritar gildi raungildanna í færibreyturnar. Ef aðferðin breytir færibreytu breytist bara afritið; breyta þess sem kallaði er óbreytt:

public static void twice(int x) {
    x = x * 2;
    System.out.println("í twice: " + x);
}

public static void main(String[] args) {
    int n = 5;
    twice(n);
    System.out.println("í main: " + n);
}
í twice: 10
í main: 5

Þess vegna virkar absDiff í Rectangle-dæminu: hún víxlar a og b innan sín án þess að það hafi áhrif á hnitin í main. Og þess vegna er ekki hægt að skrifa swap(int a, int b) sem víxlar breytum þess sem kallar.

Fylki og hlutir: þá er tilvísunin afrituð, ekki fylkið sjálft. Aðferðin getur því breytt innihaldi fylkis eða hlutar sem sá sem kallaði sér (kaflar 7 og 9). En ef hún lætur færibreytuna vísa á nýtt fylki sér sá sem kallaði það ekki.

Svið breyta

Staðvær breyta (local variable) er til frá yfirlýsingu og til loka blokkarinnar { } sem hún er í. Færibreytur eru staðværar breytur aðferðarinnar. Tvær aðferðir mega hafa breytur með sama nafni; þær eru óháðar. Ekki má lýsa tveimur breytum með sama nafni í sömu eða hreiðraðri blokk.

public static void demo() {
    int x = 1;
    for (int i = 0; i < 3; i++) {
        int y = i * x;      // y er bara til í lykkjunni
    }
    // System.out.println(y);  // þýðingarvilla: y er ekki til hér
    // int x = 2;              // þýðingarvilla: x er þegar til
}

Yfirhleðsla (overloading)

Margar aðferðir mega heita sama nafni ef færibreyturnar eru ólíkar (fjöldi eða tög). Þýðandinn velur þá sem passar best við raungildin; nákvæm samsvörun er tekin fram yfir víkkun.

static int max(int a, int b)          { return a > b ? a : b; }
static double max(double a, double b) { return a > b ? a : b; }
static int max(int a, int b, int c)   { return max(max(a, b), c); }

max(3, 7)        // int-útgáfan → 7
max(3, 7.5)      // double-útgáfan (3 víkkað) → 7.5
max(1, 9, 4)     // þriggja færibreytu útgáfan → 9

Aðferðir sem eru eins nema skilatagið eru ekki löglegar yfirhleðslur (þýðingarvilla). copy(int[]) og copy(int[][]) í MultiArrays eru dæmi um yfirhleðslu.

Að brjóta vandamál upp

Góð aðferð gerir eitt og nafnið segir hvað. Í Snakes & Ladders sér visualizeBoard(offset, square) um að teikna borðið, svo leikjalykkjan í main verður stutt og læsileg. Hönnunin er ofan frá (top-down): skrifaðu aðalreikniritið með köllum á aðferðir sem eru ekki til enn, og útfærðu þær svo eina í einu og prófaðu hverja sér.

Samantekt

  • public static Skilatag nafn(Tag p1, Tag p2) { … return …; }
  • Aðferð með skilatag þarf return á öllum leiðum; return hættir strax.
  • Gildisfærsla: breytingar á færibreytum af frumtagi sjást ekki hjá þeim sem kallaði.
  • Staðværar breytur lifa í sinni blokk.
  • Yfirhleðsla: sama nafn, ólíkar færibreytur (ekki bara ólíkt skilatag).
