Erfðir og fjölbrigðni

Tengist: Miðannarpróf 2 og lokapróf: extends, super, yfirskrifun, fjölbrigðni

Dráttarbunki og kastbunki eru báðir hlaðar af spilum; mennskur leikmaður og tölvuleikmaður eru báðir leikmenn sem gera á sinn hátt. Erfðir láta undirklasa endurnýta og sérhæfa yfirklasa, og fjölbrigðni lætur sama kallið gera mismunandi hluti eftir því hver hluturinn raunverulega er. Þetta er kjarninn í seinni hluta prófsins: smiðakeðjur, yfirskrifun og „hvaða aðferð er keyrð?“.

extends: yfirklasi og undirklasi

public class StackOfCards {               // yfirklasi (superclass)
    protected Card[] cards = new Card[112];
    protected int top = -1;
    protected void push(Card c) { cards[++top] = c; }
    protected Card pop()        { return cards[top--]; }
    public boolean isEmpty()    { return top == -1; }
}

public class DiscardPile extends StackOfCards {  // undirklasi (subclass)
    public void discard(Card c) { push(c); }     // notar erfða aðferð
    public Card topCard()       { return cards[top]; }
}
  • Undirklasinn erfir öll eigindi og aðferðir yfirklasans og getur bætt við nýjum og yfirskrifað (override) erfðar aðferðir.
  • Sambandið er „er“ (is-a): DiscardPile er StackOfCards. Ef það er bara „hefur“ á að nota eigindi (kafli 9), ekki erfðir.
  • Java leyfir aðeins einn yfirklasa (single inheritance). Allir klasar erfa á endanum frá Object.
  • private eigindi yfirklasans eru til í undirklasanum en hann má ekki nota þau beint; hann notar public/protected aðferðir eða gerir þau protected.

Af hverju í UNO? Ef drawPile og discardPile væru bæði StackOfCards gætu allir ýtt og tekið af báðum. Með undirklösum og protected aðferðum í StackOfCards býður hvor bunki aðeins upp á þær aðgerðir sem eiga við: úr dráttarbunka er bara dregið og í kastbunka er bara kastað.

Smiðir og super(…)

Smiðir erfast ekki. Smiður undirklasans byrjar alltaf á því að kalla á smið yfirklasans, svo erfði hlutinn sé frumstilltur fyrst:

public class Player {
    private String name;
    public Player(String name) { this.name = name; }
    public String getName() { return name; }
}

public class ComputerPlayer extends Player {
    private int level;
    public ComputerPlayer(String name, int level) {
        super(name);          // verður að vera FYRSTA setningin
        this.level = level;
    }
}
  • Ef þú skrifar ekki super(…) setur Java inn super(); (án færibreyta) sjálfkrafa.
  • Ef yfirklasinn hefur engan smið án færibreyta (t.d. bara Player(String name)) og undirklasinn kallar ekki á super(name) er það þýðingarvilla.
  • Smiðakeðjan keyrir því ofan frá: Object → Player → ComputerPlayer. Það sem smiður yfirklasans prentar kemur á undan því sem undirklasinn prentar.

Yfirskrifun (overriding)

Undirklasi yfirskrifar aðferð með því að skilgreina aðferð með sömu undirskrift (og samhæfðu skilatagi). Merkið @Override lætur þýðandann athuga að þú sért í raun að yfirskrifa eitthvað. super.aðferð() kallar á útgáfu yfirklasans:

public class Triangle extends Polygon {
    @Override
    public String toString() {
        return "Triangle " + super.toString();   // bætir við útgáfu Polygon
    }
}

public class DrawPile extends StackOfCards {
    @Override
    public Card pop() {
        if (isEmpty()) {
            fill(UnoGame.discardPile.flush());   // fylla á úr kastbunkanum
        }
        return super.pop();                      // svo venjulega pop
    }
}

Yfirskrifuð aðferð má ekki hafa þrengri aðgang (public → private er villa), en má víkka hann (protected → public). final aðferð má ekki yfirskrifa og frá final klasa má ekki erfa (t.d. String).

Fjölbrigðni og breytileg binding

Breyta af tagi yfirklasa má vísa á hlut af undirklasa: Player p = new HumanPlayer();. Þá skiptir máli:

Yfirlýst tag (declared type) breytunnar, hér Player, ákveður við þýðingu hvaða aðferðir má kalla á.

Raunverulegt tag (actual type) hlutarins, hér HumanPlayer, ákveður við keyrslu hvaða útgáfa er keyrð (breytileg binding, dynamic binding).

Player[] players = { new HumanPlayer(), new ComputerPlayer(), new ComputerPlayer() };
for (Player p : players) {
    p.playTurn(currentCard);   // hver leikmaður gerir á sinn hátt
}

Þetta er fjölbrigðni (polymorphism): leikjalykkjan þarf ekki að vita hvers konar leikmenn eru með. Nýja leikmannategund má bæta við án þess að breyta henni.

Breytileg binding gildir líka inni í yfirklasanum: ef aðferð í Polygon kallar á calcArea() er útgáfa raunverulega hlutarins keyrð.

class A {
    void hi()   { System.out.println("A.hi"); }
    void both() { hi(); }              // hvaða hi?
}
class B extends A {
    @Override
    void hi()   { System.out.println("B.hi"); }
    void only() { System.out.println("B.only"); }
}

A x = new B();
x.hi();
x.both();
// x.only();   // þýðingarvilla: A hefur ekki only()
((B) x).only();
B.hi

Kast á hlutum og instanceof

  • Upp (upcast), undirklasi → yfirklasi, er sjálfkrafa: Player p = new HumanPlayer();
  • Niður (downcast) þarf kast: HumanPlayer h = (HumanPlayer) p;. Ef hluturinn er í raun ekki HumanPlayer kastast ClassCastException við keyrslu.
  • obj instanceof Klasi er true ef hluturinn er af þessum klasa eða undirklasa hans. Notaðu það áður en þú kastar niður. (null instanceof X er false.)
if (p instanceof HumanPlayer) {
    HumanPlayer h = (HumanPlayer) p;

Klasinn Object: toString og equals

Allir klasar erfa frá Object, sem hefur m.a. toString() (skilar Klasi@kóði) og equals(Object o) (sem er ==, þ.e. sami hlutur). Til að bera saman innihald yfirskrifarðu equals; færibreytan verður að vera af tagi Object, annars ertu að yfirhlaða, ekki yfirskrifa:

@Override
public boolean equals(Object o) {
    if (!(o instanceof Card)) return false;
    Card other = (Card) o;
    return number == other.number && color == other.color;
}

Samantekt

  • extends = „er“; einn yfirklasi; allt erfir frá Object.
  • Smiður undirklasa kallar fyrst á super(…) (sjálfkrafa super() ef ekkert er skrifað); keyrslan fer ofan frá.
  • Yfirskrifun: sama undirskrift, valin við keyrslu. Yfirhleðsla: ólíkar færibreytur, valin við þýðingu.
  • Yfirlýst tag ákveður hvað má kalla á; raunverulegt tag ákveður hvað keyrir.
  • Upcast sjálfkrafa; downcast með kasti, varið með instanceof.
  • equals(Object o) til að yfirskrifa; super.toString() til að bæta við.
