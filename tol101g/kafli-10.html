Erfðir og fjölbrigðni

Tengist: Miðannarpróf 2 og lokapróf: extends, super, yfirskrifun, fjölbrigðni

Mennskur leikmaður og tölvuleikmaður eru báðir leikmenn; dráttarbunki og kastbunki eru báðir bunkar. Með erfðum skrifarðu það sameiginlega einu sinni og bætir bara við því sem er öðruvísi. Þetta er stór hluti af seinni hluta prófsins.

Í lok kaflans geturðu

  • skrifað undirklasa með extends og super(…)
  • yfirskrifað aðferð og notað super.aðferð()
  • sagt hvaða aðferð keyrir þegar breytan og hluturinn eru ekki af sama tagi

1 extends: „er“

class Vehicle {
    private String name;
    public Vehicle(String name) { this.name = name; }
    public String getName() { return name; }
    public String describe() { return name + " keyrir"; }
}
class Bicycle extends Vehicle {
    private int gears;
    public Bicycle(String name, int gears) {
        super(name);              // smiður Vehicle FYRST
        this.gears = gears;
    }
    public int getGears() { return gears; }
}
// í main:
Bicycle b = new Bicycle("DBS", 21);
System.out.println(b.describe());     // erft frá Vehicle
System.out.println(b.getGears());
DBS keyrir
21

Hvenær? Þegar setningin „B er A“ er sönn (reiðhjól er farartæki). Ef „A hefur B“, notaðu eigindi í staðinn (kafli 9).

Tvær reglur um smiði: (1) super(…) verður að vera fyrsta línan. (2) Ef yfirklasinn hefur engan smið án færibreyta verður þú að kalla á super(…), annars þýðist kóðinn ekki.

private erfist en er falið: Bicycle má ekki skrifa name beint. Notaðu getName(), eða gerðu eigindið protected.

2 @Override: gera öðruvísi

class Shape {
    public String toString() { return "Lögun"; }
}
class Triangle extends Shape {
    @Override
    public String toString() {
        return "Þríhyrningur (" + super.toString() + ")";
    }
}
// í main:
System.out.println(new Shape());
System.out.println(new Triangle());
Lögun
Þríhyrningur (Lögun)

Undirklasinn skrifar aðferð með sama nafni og sömu færibreytum; hans útgáfa gildir þá fyrir hans hluti. super.toString() kallar á útgáfu yfirklasans, svo þú getur bætt við í stað þess að skrifa allt upp á nýtt.

Settu alltaf @Override: þá kvartar Java ef þú skrifaðir nafnið eða færibreyturnar rangt.

3 Hvaða aðferð keyrir? (prófið!)

class Player {
    public String play() { return "?"; }
    public String turn() { return "Leikmaður: " + play(); }
}
class Human extends Player {
    @Override public String play() { return "velur spil"; }
}
class Computer extends Player {
    @Override public String play() { return "reiknar"; }
    public int level() { return 3; }
}
// í main:
Player[] players = { new Human(), new Computer() };
for (Player p : players) {
    System.out.println(p.turn());
}
Player p = new Computer();
System.out.println(((Computer) p).level());
Leikmaður: velur spil
Leikmaður: reiknar
3

Hvað MÁ kalla á? Ræðst af tagi breytunnar (Player). p.level() er villa því Player hefur ekki level().

Hvað KEYRIR? Ræðst af raunverulega hlutnum (new Computer()), líka þegar kallið kemur innan úr Player (turn() → play()).

Af hverju er þetta gott? Leikjalykkjan þarf ekki að vita hvers konar leikmenn eru með: for (Player p : players) p.play(); virkar fyrir allar tegundir, líka þær sem þú bætir við seinna.

4 Kasta á milli taga og instanceof

Player p = new Human();            // upp: sjálfkrafa
if (p instanceof Computer) {       // er þetta í raun Computer?
    Computer c = (Computer) p;     // niður: þarf kast
    System.out.println(c.level());
}

Varúð: rangt kast (Human í Computer) hrynur með ClassCastException. Spurðu fyrst með instanceof.

5 equals fyrir þína klasa

@Override
public boolean equals(Object o) {          // færibreytan VERÐUR að vera Object
    if (!(o instanceof Card)) return false;
    Card other = (Card) o;
    return number == other.number && color == other.color;
}

Gildra: equals(Card other) lítur rétt út en yfirskrifar ekki (það býr til nýja aðferð). @Override myndi grípa það.

7 Úr tímanum: DrawPile erfir StackOfCards

public class DrawPile extends StackOfCards {
    @Override
    public Card pop() {
        if (isEmpty()) {                               // tómur bunki?
            fill(UnoGame.discardPile.flush());         // fylla á úr kastbunkanum
        }
        return super.pop();                            // svo venjulega pop
    }
}

Dráttarbunkinn er bunki með einni breytingu: hann fyllir á sig sjálfur. Allt hitt (push, isEmpty…) erfir hann óbreytt.
